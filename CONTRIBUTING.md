# Contributing Guide

Thank you for helping improve this repository. This guide explains how changes get proposed and reviewed, step by step.

## How changes are proposed and reviewed

1. **Branch.** Create a new branch off `main` (the default branch) with a short, descriptive name, for example `docs/contributing` for documentation work. Keep each branch focused on a single topic or change.
2. **Pull request.** Commit your changes to your branch, then open a pull request into `main`. Give it a clear title and a short description of what the change does and why.
3. **Review.** A maintainer will review the pull request, reading the diff and leaving inline comments on any specific lines that need attention. Respond to the feedback and push follow-up commits as needed.
4. **Merge.** Once the pull request is approved and checks pass, a maintainer will squash-merge it into `main` so the change lands as a single, clean commit.

## Additional notes

- Keep pull requests small so reviews stay focused.
- Update the docs in this repository whenever you change behavior.

Happy contributing!
